# Kickbase – guide for the AI agent

You control **Kickbase**, a psytrance kick + bass synth, through MCP tools. This is the manual. The companion `get_guide topic=psytrance` explains what a good psytrance kick and bass is (read it before designing sounds). Facts here describe how *this* synth works; where the two documents disagree, this one wins. For building and judging a sound step by step (what to listen for, mixing the kick with the bass), read `get_guide topic=school` once per session.

## 1. The loop

1. `get_guide` (this), `get_guide topic=psytrance` and `get_guide topic=school` once per session.
2. `list_presets` / `load_preset` for a starting point, or `reset` for the Init sound.
3. Change things: `set_parameters`, `set_effect`, `set_kick_envelopes`, `set_pattern`, `set_sidechain_curve`, `set_modulation`.
4. `render_preview` (full, then `part=kick` and `part=bass` separately). Read the **metrics**, the **checks** and look at the **spectrogram image**. You cannot hear: the numbers and the picture are your ears.
5. Adjust and repeat. Use `undo` freely. Save with `save_preset` (it appears in the plugin's preset menus; ask the user to listen).
6. Always tell the user what you changed and why, and that you could only measure, not listen.

Access key: if the user set an access key in the plugin (SETTINGS tab, AI LINK), the bridge needs the same key in its environment (`KICKBASE_KEY`, or `install-mcp.ps1 -Key <key>`), otherwise every call is refused with an "access key" error: tell the user.

Instances: `list_instances` shows `headless` (private, no DAW, always available) and any Kickbase in a DAW whose **AI button** (top bar) is on. `use_instance` switches. Changes in a DAW instance are audible immediately; `render_preview` still renders offline from a copy.

## Live Code modulation

`live_code_create` accepts Strudel code and writes its note patterns to the piano roll. It can also put a modulation on a note pattern:

- `.lfo(paramId, hz, depth, shape?)` adds a free-running LFO. Example: `note("c2").lfo("bass1Cutoff", 2, 0.5, "tri").s("i1")`. The optional shape is `sine` (default), `tri`, `saw`, `isaw`, `square` or `rand`.
- `.env(paramId, attackMs, decayMs, depth?)` adds an attack/decay envelope triggered by new notes on that instrument. Example: `note("c2").env("bass1Cutoff", 10, 200, 0.5).s("i1")`. This is AD (not ADSR) and is not supported on the kick.

Use a modulatable sound parameter id from `list_parameters`; unsupported ids and non-modulatable controls are skipped and listed in `data.problems`, while the note rows are still written. CODE 1-8 are internal sources: they are not saved in projects or presets, and hand-drawn modulation menus do not offer them.

In the LIVE CODE tab the code can also set parameters and effect slots (not in `live_code_create`): `bass1.cutoff.set(0.4)`, `fx1.slot2.setEffect("reverb")` (type name lowercase, letters and digits only) and `fx1.slot2.mix.set(0.3)` (knob name lowercase, in real units). A knob can only be set when the slot holds an effect that has it; the error line names the slot. Only changed values are written, so a hand change stays until the code changes.

## 2. What the synth is

One plugin: **kick** + **1-10 instruments** (default 3; `set_instruments`) + sidechain + **11 FX channels (FX1–FX11)** + mixer + master.

- **Instruments** (bass layers, `bass1…bass10`): each has its own pattern, three wavetable oscillators + a sample, filter, envelopes, FX send and sidechain depth. `instrumentCount` (set it with `set_instruments`, not `set_parameters`) is how many are used. Removing instruments deletes the last ones completely. `edit_instrument` is the instrument menu (rename, colour `#rrggbb`, duplicate, move_up/move_down, delete): the whole instrument moves, and name and colour are saved in the project, not as parameters. Layers are numbered 0-9 in `set_pattern`, `set_gate`, `load_preset` etc. (instrument 1 = layer 0).

- **Key**: the incoming MIDI note sets the key and *also the bass octave*. MIDI note 52 (E4) gives bass root E1 = 41 Hz and kick tail near E1; note 60 (C5 in FL) gives C2 = 65 Hz. Psytrance bass roots are 41–49 Hz (E1–G1), so the usual keys are MIDI 52–55. `render_preview` takes `note` (default 52).
- **Kick tail**: `kickKeyFollow` = Follow puts the tail on the key note within A#0..A1 (29–55 Hz), `kickTune` ±12 semitones moves it. Fixed = C1 + tune.
- **Pattern**: the kick is a note layer just like the bass layers (layer `"kick"`, grid `rowGridKick`, default 1/16): free-timed notes with velocity and a pitch in semitones that moves the kick's tail (kick melodies; 0 = the key note), no glide and no gate. Each instrument has free-timed notes (96 ticks per quarter note, 384 per bar) with pitch ±96 semitones from the key, velocity, length and an optional **glide** flag. A glide note works like an FL Studio slide note: it plays no new note, it glides the note that is sounding to its own pitch during its own length, and the pitch stays there until that note ends (a 2-bar note with a quarter-long glide note an octave up half-way through: it rises an octave over that quarter and stays up).
- **Row lengths**: there is no total length to set. Each row (the kick and every instrument) is as long as its notes: with `length: "auto"` (the default) the row ends at the last bar that has a note (at least 1 bar, a long note counts to where it ends) and shrinks again when notes are removed. `set_pattern` with `length: N` (1-1024) locks the row to N bars, for example 3 bars of notes and 1 bar of silence; `length: "auto"` unlocks it. Shortening below the notes returns an error with the number of notes that would go; give `trim: true` to remove them. In a locked row, writing a note beyond the end returns the error `row is locked to N bars`. `repeat_to: N` repeats the row's content until it is N bars. `get_state` shows per row `bars`, `length_mode` (auto|locked), `content_bars` and `extra_bars` (bars added with + BAR in the plugin), and `pattern.bars` = the longest row. The pattern is as long as the longest row. With `rowLoopKick`, `rowLoopBass1`..`10` on (default) a shorter row repeats until the longest row has played out; off, it plays once and then is silent. The old parameters `patternBars` and `rowBars*` are no longer used (kept only so that old projects load). In the plugin, use the LENGTH button of each row (click or right-click the row name) and + BAR in the piano roll.
- **Gate**: separate from the notes. Each bass layer can have a GATE: an on/off rhythm with its own grid (`bassNGateGrid`), depth (`bassNGateDepth`) and edge smoothing (`bassNGateSmooth`) that chops the layer's sound while `bassNGateOn` is true. It does not change the notes; notes can sound outside the gate. Use `set_gate`.
- **Piano roll layers**: a layer whose notes were edited in the piano roll (or written with `notes`, pitches or glide) is shown as a small piano roll in the plugin instead of step buttons, as in FL Studio. Rows can be up to 1024 bars, so a whole section can be built in one pattern; Note End (`noteEnd`) Cut/Finish bar/Finish pattern is what happens when the held key ends.
- **Piano roll files**: `save_piano_roll` / `load_piano_roll` keep a layer's notes (with glide flags, pattern length and grid) as `.roll` presets in `Documents\Kickbase\Presets\Piano Roll`, listed by `list_presets` (section Pattern) and by the PRESET button in the plugin's piano roll. They can be loaded into any layer. `export_midi` / `import_midi` write and read standard MIDI files (`note` = the key that sets the bass root, default 52); glide notes are exported as ordinary notes, and an imported file is moved by octaves to fit within ±96 semitones.
- **Signal**: layer → ducked by the kick (per-layer depth) → optionally through an FX channel (`bassNFxChannel`, `bassNFxAmount`) → mixer strip (gain, pan, SC on/off, MAX = through the maximizer or not) → master (width, mono-below, drive, clip, limiter).
- Rendering is deterministic (seeded randomness): the same sound renders bit-identically.

## 3. Units and parameter ids

Values are in the parameter's own unit: Hz, ms, dB, semitones, octaves; percentages are 0..1. Choice parameters take the option name or index; switches true/false. `list_parameters` (with `prefix`) tells you id, range, default, current value and `help` (what the knob does: the same text the user sees as its tooltip); `list_effects` gives the same for every effect knob.

- **kick**: `kickOn`, `kickKeyFollow`, `kickTune` (st), `kickPitchAmount` (scales the pitch envelope), `kickLength` (stretches both envelopes), `kickPhase`, `kickHarmonics` + `kickHarmDecay` (ms) + `kickHarmTilt`, `kickClick` (level) + `kickClickLength` (ms) + `kickClickTone` (Hz), `kickClipMode` (Soft/Hard/Tube/Fold), `kickDrive`, `kickCrush` (bit crush after the drive), `kickLowCut` (Hz, 20 = off; removes rumble under the kick), `kickHighCut` (Hz), `kickLevel`, `kickFxChannel` (None, FX1–FX11), `kickFxAmount`.
  - More layers and shapes: `kickWave` (Sine/Triangle/Soft Square/Soft Saw: the body), `kickSub` (sine one octave down), `kickFm` + `kickFmRatio` + `kickFmDecay` (FM on the body: punchier or metallic), `kickNoise` + `kickNoiseDecay` + `kickNoiseTone` (a noisy top layer: snap and air), `kickVelPitch` (velocity changes the pitch sweep).
  - Library: `list_library` lists the user's library (`Documents\Kickbase\Library`: free CC0/MIT/BSD packs and the user's own sounds marked `personal: true`; filter with `category` and `search`), and `load_library_kick` loads a Kicks item (by `id` from the list, or exact `name`) as the kick's sample: if `kickSampleMode` is Click it becomes Replace, or pass `mode`. Undo restores the previous sample. The library is read-only for the AI: it cannot import, delete or download anything (the user imports with `tool importlibrary`; fetching from Freesound is a developer tool, not part of the plugin).
  - Sample: `load_kick_sample` loads a WAV; `kickSampleMode` = Click (first moments, `kickClick` level), Layer (whole sample on top of the synth kick) or Replace (the sample is the kick); `kickSampleLevel`, `kickSampleTune` (st) apply to Layer and Replace.
- **instrument N** (`bass1…bass10`; 10 instruments exist as parameters, only the first `instrumentCount` play): `bassNOn`, `bassNLevel`, `bassNGate` (ALL LENGTHS: scales every note's length), `bassNDuck` (sidechain depth), `bassNGrid`, `bassNFxChannel`, `bassNFxAmount`, `bassNOctave` (−2..1), `bassNTune`.
  - Oscillators `bassNA…` / `bassNB…` / `bassNC…` (OSC 1-3; `bassNAOn` etc. switch each): `Table`, `Pos` (position in the wavetable), `Level`, `Semi`, `Fine` (cents), `Unison` (1–7), `Detune` (cents), `Blend`, `Warp` (Off, Sync, Bend, PWM, Mirror, FM (B) – FM only on A, OSC B modulates A even when its level is 0 – Flip, Quantize, AM), `WarpAmount`, `Phase`, `Random` (random start phase; 0 = identical attack every note), `Pan`, `Stereo` (unison spread). Also `bassNAMorph` / `bassNBMorph` / `bassNCMorph` (on = default): on, `Pos` fades smoothly between the table's waveforms; off, it jumps between them (steps: Basic 4 = sine, triangle, saw, square; other built-in tables 16; a table made from a WAV file has as many steps as the file had cycles, a single cycle 1). Steps jump, so fast modulation of `Pos` can click.
  - Tables (choice index; names or numbers both work): 120 built-in tables built on demand: Basic, PWM, Sync, Harmonics, FM, Growl, Fold, Formant, Digital, Phase Dist, **Classic Sine (10), Classic Triangle (11), Classic Saw (12), Classic Square (13)**, **User WAV (14, an oscillator's own loaded table)** and then Analog, Filter, FM, Digital, Random, Vocal, Organ, Psy, Evolve and Grit tables (use `list_parameters prefix=bass1ATable` for the whole list). Classic tables ignore `Pos`. In the plugin the TABLE menu is grouped in categories and also lists the user's library (`Documents\Kickbase\Wavetables`, WAV files and folders; a whole folder of single-cycle files can become one wavetable).
  - `bassNWarpEnv` (extra warp on A at the start of each note), `bassNSub` + `SubOctave` + `SubWave` (Sine/Triangle/Square/Saw; sub, mono), `bassNNoise` + `NoiseTone` (100 % = white, lower = darker), `PitchEnvAmount` (semitones the note starts above/below its pitch; 0 = off) + `PitchEnvDecay` (ms).
  - Filter: `FilterModel` (Kickbase = the standard filter, Ladder = a Moog-style 4-pole ladder with `FilterType` and `FilterP1` = drive, Formant = vowel filter (`Cutoff` shifts the formants, `Resonance` narrows them, `FilterP1` = morph A-E-I-O-U, `FilterP2` = blend), Comb = feedback comb filter (`Cutoff` = comb pitch, `Resonance` = feedback, `FilterP1` = damping, `FilterP2` = blend), `FilterP1`/`FilterP2` (0..1, used by Ladder, Formant and Comb only, default 0 and 1), TB-303 = an emulation of the Roland TB-303 filter: 24 dB low-pass ladder with a high-pass in the feedback path, squelchy at high `Resonance`; the cutoff is clamped to 200-20 000 Hz; `FilterType` is ignored with TB-303; accent = velocity, slide = glide notes; about 3x the CPU), `FilterType` (LP 24, LP 12, Band, High), `KeyTrack`, `Cutoff` (Hz), `Resonance`, `EnvAmount` (octaves the envelope opens the filter), `EnvAttack` (ms, how fast it opens; default 1), `EnvDecay` (ms), `VelToEnv` (accent: velocity opens the filter more).
  - Filter 2 (the FILTER tab shows both filters and a response curve): `Filter2On` (off by default: it then costs no CPU and changes nothing), `Filter2Model` (same list as `FilterModel`), `Filter2Type`, `Filter2Cutoff`, `Filter2Reso`, `Filter2P1`, `Filter2P2` (same meaning per model as the Filter 1 fields), `FilterRouting` (Serial = Filter 1 then Filter 2, Parallel = both get the same sound), `FilterMix` (Serial: how much of Filter 2 you hear, 0 = Filter 1 only; Parallel: balance between Filter 1 (0) and Filter 2 (1)). Filter 2 has no envelope or key tracking of its own; move `Filter2Cutoff` with ENV 2/3, an LFO or the matrix for a sweep.
  - Amp: `Attack`, `Decay`, `Sustain`, `Release` (ms), `Drive` + `DriveMode` (Soft, Hard, Fold, Asym, Crush). (`Glide` is no longer used: a glide note glides during its own length.)
  - Modulation envelopes: `Env2Attack/Decay/Sustain/Release` and `Env3…` (ms, sustain 0..1): they do not play the sound, they are sources for `set_modulation` (source "ENV 2" / "ENV 3" of an instrument), together with the note's `VELOCITY` and a `RANDOM` value per note. `Env2Mode` / `Env3Mode` (ms | Sync, default ms) with `Env2AttackSync`/`Env2DecaySync`/`Env2ReleaseSync` (and Env3…): in Sync the times are note lengths that follow the tempo (0, 1/64, 1/32, 1/16 T, 1/16, 1/16 D, 1/8 T, 1/8, 1/8 D, 1/4 T, 1/4, 1/4 D, 1/2, 1 bar, 2 bars, 4 bars); sustain is a level and is not affected.
  - Gate: `GateOn`, `GateGrid`, `GateDepth` (0..1), `GateSmooth` (ms).
  - Sample (a third sound source next to the oscillators, loaded with `load_bass_sample`): `SampleLevel`, `SampleRoot` (MIDI note the sample was recorded at, C5 = 60), `SampleKey` (Off/On: follow the played notes), `SampleLoop` (Off/On), `SampleStart` (0..1). It goes through the filter and amp envelope; set `ALevel` and `BLevel` to 0 to hear it alone.
- **sidechain**: `scMode` (Kick envelope | Curve), `scLength` (Kick, 1/16, 1/8, 3/16, 1/4, 1/2), plus `bassNDuck` per instrument and `fxXDuck` per FX channel. Use `set_sidechain_curve` for curve points.
- **FX channels** FX1–FX11 (parameter ids `fxA…fxK`: FX1 = `fxA`, FX2 = `fxB` … FX11 = `fxK`): `fxALevel` (0..1.5), `fxADuck`, EQ (`fxAEqHp`, `fxAEqLp`, `fxAEq1F/1G/1Q … 4F/4G/4Q`), compressor (`fxACompThr/Ratio/Att/Rel/Makeup`; ratio 1 = off). Slots with effects: `set_effect`.
- **mixer**: `mix<Kick|Bass1…Bass10|FxA…FxK><Gain|Pan|Duck|Max>` (Gain in dB −60..+12; Duck = sidechain applies, not for the kick; Max = goes through the maximizer).
- **master**: `masterOn`, `masterDrive` (dB), `masterClip`, `masterCeiling` (dB), `masterWidth`, `masterEnhance`, `masterMonoBelow` (Hz), `masterRelease`, and `gain` (output).
- **LFOs**: the instrument has up to 10 (`lfo1…lfo10`; the FX plugin has `lfo1…lfo3`). LFO 1-3 always exist; 4-10 are added when needed: `set_modulation` on an inactive LFO, or a route from it, adds it, and `{"lfo":7,"remove":true}` removes it with its routes. `get_state` lists `active_lfos`. Each has `On`, `Shape` (Sine, Triangle, Saw Up, Saw Down, Square, Random, **Custom**), `Rate` (tempo synced, 1/32 … 16 bars), `Mode` (Sync | Hz) and `Hz` (0.02–40, its own speed), plus `Snap` (on/off, default off) and `SnapRange` (1–25 %, default 5): in Hz mode, when the free rate is within the range of a note value (1/8, 1/4 T ...) at the current tempo, it locks exactly to it. Changing the rate (Hz, Sync or Mode) or the tempo never restarts the LFO phase; it continues from where it is. A Custom LFO is a curve of points: write it with `set_modulation` `lfos:[{"lfo":1,"points":[[0,0,0],[0.25,1,0],[0.5,-0.5,-0.4],[1,0,0]]}]` (phase 0..1, value -1..1, tension -1..1 bends the segment to the next point); routes with `set_modulation`. The instrument's envelopes (volume, filter, ENV 2, ENV 3) are drawn and edited as diagrams on the plugin's ENV tab.
- **Macros**: `macro1…macro4` (0..1): knobs you turn yourself (or automate) that can move other knobs through routes (source "macro" 1-4).
- **Matrix** (`set_modulation`): up to 64 routes. A route is a source (`lfo` 1-10, FX 1-3, `macro` 1-4, or `instrument` 1-10 with `source` "ENV 2" | "ENV 3" | "VELOCITY" | "RANDOM" | "AMP ENV" | "FILT ENV"; AMP ENV is the volume envelope ENV 1 and FILT ENV the filter envelope's shape 0..1 without its amount, both 0 when that envelope is switched off; `get_state` shows them as e.g. "INSTR 2 AMP ENV"), a `param` (any kick*, bass*, fx* knob) and an `amount` (-1..1 of the knob's travel).

## 4. Kick envelopes

`set_kick_envelopes` takes nodes `[time_seconds, value, tension]`.
- **pitch**: semitones above the tail pitch, 0..72, up to 0.5 s. Example psy kick: `[[0,38,-0.65],[0.010,17,-0.45],[0.035,4,-0.3],[0.085,0.4,-0.2],[0.12,0,0]]` (start ~38 semitones above the tail, settles within ~100 ms).
- **amp**: volume 0..1, up to 2 s. The kick ends at the last node, which must be 0. Example: `[[0,0,0],[0.0005,1,0],[0.03,1,0],[0.075,0.78,0.15],[0.19,0,0.35]]`.
- Tension: a segment moves as `t^(4^tension)`. Negative = fast first, then slow; positive = holds, then moves late.
- Keep the whole kick ≤ one eighth note (≈ 207 ms at 145 BPM). `render_preview part=kick` measures length and tail.

## 5. The pattern language (`set_pattern`)

Bass layer: `bars` = one text per bar (the list repeats to fill the pattern length; give up to 64 distinct bars), `grid` = step resolution ('1/16', '1/8', '1/8 T', '1/16 T', '1/32', '1/64', '1/4'). Words separated by spaces or `|`:
- `.` rest
- `g` ghost (42 %), `m` soft (62 %), `x` normal (80 %), `X` accent (100 %) velocity
- then optionally pitch (`+7`, `-5` semitones from the key), `~` makes it a **glide note** (no new note: it glides the sounding note to this pitch during its own length), `:50` length as percent of the step

Examples (grid 1/16, 16 words per bar): classic rolling `". m x x . m x x . m x x . m x x"`; with a melodic turn in beat 4: `". m x x . m x x . m x x . m+3 x+7 X+12"`; hypnotic gaps `". m . x . m x . . m . x . m x ."`. Triplet K-B-B: grid `1/8 T`, `". x x . x x . x x . x x"`. Offbeat: grid `1/8`, `". x . x . x . x"`.
Or exact `notes`: `[{"tick":0,"length":24,"pitch":0,"velocity":0.8,"slide":false}]`.
Kick: layer `"kick"`, same pattern language as the bass layers (x = full volume, m/g softer, `+7` = pitch in semitones) or the short form of 16 characters `x`/`.`: `["x...x...x...x..."]`. The kick can also be written with `notes` and edited in the piano roll (`save_piano_roll`, `export_midi` etc. take layer `"kick"`).
A glide note needs a sounding note to glide: write a long note, then a short `~` note later inside it, e.g. a 1/16 grid with a one-bar note and `~` words with pitch: use `notes` for exact control (the long note `{"tick":0,"length":384}` and the glide `{"tick":192,"length":96,"pitch":12,"slide":true}`). Gate steps: `set_gate` with `bars` of `x` (open) and `.` (closed).

## 6. Effects

`list_effects` gives all 15 types and their knobs. The **Maximizer** (GAIN, CLIP, CEILING, RELEASE, MIX; no latency) is a loudness maximizer you can put on one channel only: send the kick to a channel with a Maximizer (`kickFxChannel`, `kickFxAmount` = 1) to make the kick loud and even on its own, separately from the master maximizer. Use `set_effect` with channel FX1–FX11, slot 1–5, type and knobs by name. Sources reach a channel through their sends (`bassNFxChannel` = 1 for FX1 … 11 for FX11; `bassNFxAmount` = how much goes through, the rest stays dry); the channel returns with its `Level` and `Duck`. For parallel effects (reverb, echo) send a moderate amount and give the channel an EQ high-pass (`fxAEqHp` ≈ 150–300 Hz for FX1) so the low end stays clean, and `fxADuck` so tails pump with the kick.
The Echo is modelled on FL's Fruity Delay 2 (TIME, OFFSET, IN PAN, IN VOL, FB MODE Normal/Invert/Ping-pong, FEEDBACK, CUT, DRY VOL; echoes are IN VOL × input, the dry sound DRY VOL).

## 7. What `render_preview` tells you

Metrics: peak (dBFS), RMS, DC offset, spectral centroid (Hz), energy per band relative to the total (<60, 60–250, 250–1k, 1–5k, >5k Hz), side-vs-mid overall and below 150 Hz, and for `part=kick` the kick length (ms) and the tail frequency (Hz). **Checks**: finite audio, no clipping (peak ≤ −0.3 dBFS), small DC, bass mono below 150 Hz, kick ≤ 1/8 note, kick tail within about two semitones of the bass root.
The spectrogram has a log frequency axis 20 Hz–20 kHz, bright = loud, vertical lines are beats (numbers = bars). For a kick close-up the time axis is the first 0.4 s: look for the pitch sweep falling from the top to a steady line at the tail frequency, and for the click as a short broadband smear at the very start. Bass: look for the filter envelope (brightness opening and closing each note) and a clean, steady fundamental.

Also check yourself: the first bass note after a kick is a little softer (rolling feel); notes do not overlap (lower `bassNGate`, or shorten notes); the bass fundamental and kick tail are tonally related (same note/octave is a starting point, not a universal target; compare small tuning differences); wide/unison sounds stay narrow in the low end (`masterMonoBelow` helps, but keep `Stereo` modest on low layers).

## 8. Pitfalls

- A row grows with its notes (AUTO) or is locked to a number of bars; a note is never kept beyond the end of its row.
- Do not confuse note LENGTH (`bassNGate`, how long notes sound) with the GATE (an on/off chopping rhythm). A glide note is not a normal note: with nothing sounding it plays as a normal note.
- `bassNLevel` is the layer's own volume; the mixer gain (`mixBass1Gain`) comes after it. Use one of them consistently.
- Groove: `patSwing` (0-1, the off-beat sixteenths of the instruments come later; 1 = triplet feel), `patHumanize` (0-1, every instrument note a random 0-20 ms late) and `bassNDelay` (ms 0-50, an instrument's notes later, e.g. to let the kick come first), `bassNSwing` and `bassNHumanize` (an instrument's own swing/humanize, added to the pattern's). The kick stays on the grid; notes can only be moved later. Kick sample: `kickSampleOffset` (ms, -20..20: plus = the sample starts later, minus = it starts that far into the sample; use it when sample and synth kick cancel in phase).
- The mixer comes BEFORE the master limiter, but an instrument's strip (`mixBassNGain`) only scales its DRY part. The part sent to an FX channel (`bassNFxAmount`) is scaled by that channel's strip (`mixFxAGain` ... `mixFxKGain`). To lower an instrument that is sent 100 % to FX channel 1, lower `mixFxAGain` (or `bassNLevel`, which scales both). The analysis measures each instrument BEFORE the mixer (so its peak and rms do not change with the mixer gain); the Master source is after everything.
- Levels in the analysis: `sample_peak_db` / `rms_db` are real signal levels (dBFS; above 0 = clipping before the limiter). `peak_band_db` and `band_db` are the level of the energy inside one frequency band: a value above 0 there is normal and is NOT clipping.
- Presets `section=Bass` store an instrument's sound, including its EQ, sample and own wavetables (not its on/off, note length, GATE, delay, swing, humanize, duck, grid or sends); `Kick` the kick's sound (not its on/off or send); `Full` stores everything, including the oscillators' own wavetables. `Master` is the maximizer only (on, drive, clip, ceiling, release), `Soundstage` is width, mono-below and enhance, `Sidechain` is mode, length, curve and the per-instrument duck depth; none of them store routes (which sources go through the maximizer or are ducked: those are the mixer's SC/MAX buttons, kept only by `Full`). `Effects` is one FX channel (`layer` = channel 0-10). Instrument/kick presets can link an FX preset and pattern presets an instrument/kick preset (a name, not a copy); `load_preset` puts a linked effect on the first free FX channel (skipped if none is free) and loads a pattern without its linked instrument. User presets are plain files in `Documents\Kickbase\Presets\<Section>`.
- FX knob parameters (`fxA1P1…`) are normalized 0..1 and depend on the slot's type: always use `set_effect`.
- The user wants **intuitive, clear** sounds with good names; do not leave a project in a half-edited state without saying so; never claim to have heard a sound.

## 9. Checking the mix: `analyse_mix`, EQ and SIDECHAIN

- `analyse_mix` STARTS an analysis and returns at once (it runs in the background, a few seconds up to half a minute depending on the project, and the plugin keeps working). Then call `get_mix_report` (it returns `status: running` with `progress`, or the finished report); repeat until it is done. Do not change the sound or the pattern while it runs: the analysis uses them as they were when it started. It plays the pattern through once offline (all bars of the pattern, at most 16) and reports what to look at, bar by bar: collisions between the kick and instruments (and between instruments), an instrument covering the kick, a kick tail tuned too low (< 30 Hz) or high (> 62 Hz), instruments that are out of tune with each other or the kick (octaves and unison count as in tune), rumble under 30 Hz, a master limiter that works too hard, and with `reference_file` where the master has more or less energy than a reference track. Each finding has `severity` (problem, warning, info), `sources`, `low_hz`/`high_hz` and `bars`. The user sees the same report in the ANALYZER tab (ANALYSE).
- **All the data.** `get_mix_report` gives the findings and a short overview. For everything the analysis measured, pass `detail: "bars"` or choose with `include` (findings, sources, bars = band levels for every source and every bar, harmonics = the fundamental and harmonic series for every source and bar, spectra = a 1/12-octave spectrum per source and bar, kicks = every kick hit with how much each instrument is ducked, synth = ALL the settings: every parameter incl. oscillators and wavetables, filters, effects, modulation, pattern and notes). Use `sources: ["kick","instr 2"]` to limit it: the data is large with many sources. `save_mix_report` writes a JSON file with everything including the level of every frequency band in every frame (about every 43 ms) through the whole loop: use it when the user wants the analysis for another AI or for studying by hand, and tell them the path. The user can do the same from the plugin (ANALYZER tab > ANALYSIS + REPORT > EXPORT, with checkboxes for what to include).
- **Choose what you need.** `include` accepts any of: findings, sources, bars, harmonics, spectra, dynamics (level, crest, brightness, energy in six frequency ranges), kicks, presets, overview (all settings arranged by section: kick, instruments with oscillators A/B/C and wavetable names, filters, envelopes, EQ and sends, effect channels with their slots, master, mixer, modulation), synth (flat parameter list and the pattern notes, plus `pattern_timeline`), about (an explanation for a reader who knows nothing about Kickbase), frames (the spectrogram, file only). Limit it with `sources`, `bars` (e.g. `[3,4]` or `"1-4"`), `min_hz`/`max_hz` and, for the file, `frame_step`. Start small (the findings, then the bars and sources they name) and ask for more only if you need it.
- **Write your fixes into the plugin.** After analysing, call `add_report_note` for each thing you suggest or change (`title`, `text`, `finding` = the number of the finding in the list, `applied: true` if you already made the change, otherwise it is a suggestion). The notes appear in the report box of the plugin's ANALYZER tab under the findings, so the user sees what you found and what you did without reading the chat.
- It measures the real signals after ducking and EQ, so a collision the sidechain already solved does not show. Kick and instrument sharing low frequencies is only a warning (normal when the sidechain gives the kick the hit). `sensitivity` low/normal/high scales how close in level, how loud and for how long something must be to count. Raise it only when the user wants the small things. Do not "fix" info findings unless asked.
- **Do not overclaim what the report proves.** The analysis is mono, uses ~171 ms FFT windows, measures instrument sources before their FX sends (effect tails appear in Master), and excludes external DAW tracks/automation. It does not measure stereo phase/correlation or prove kick/bass phase cancellation; the kick-tail estimate below about 40 Hz is approximate and very short transients are smeared. A reported frequency collision is not itself proof of bad phase or bad sound. For suspected phase/timing problems, render isolated parts and the sum, compare level-matched A/B in mono, and ask the user to listen. `kickSampleOffset` only offsets the kick sample against its synth layer; it is not a kick-to-bass phase control.
- **Tuning advice is not universal.** Source material disagrees between matching the kick tail to the bass root, placing it a few semitones above, or choosing a fixed sweet spot. Use measured tail/key and the user's musical target; compare alternatives instead of automatically retuning. The 40-55 Hz region is a useful psytrance starting range, not a requirement for every key or style.
- Run it after a change to check that you fixed what you meant to. The fixes it suggests:
  - **EQ** for the kick, each instrument and the master: parameters `kickEqHp`, `kickEq1F`/`kickEq1G`/`kickEq1Q` ... `kickEq4Q`, `kickEqLp` (instrument n: `bassnEq...`, master: `masterEq...`). Bands 1 and 4 are low/high shelves, 2 and 3 bells. Gain is in dB, neutral by default (no processing). The high-pass `EqHp` (20 = off) is the usual fix for rumble.
  - **Ducking one source under another**: put an effect of type `Sidechain` in an FX channel (`set_effect`, knobs SOURCE = Kick or Instr 1-10, THRESHOLD, DEPTH, ATTACK, RELEASE), and send the instrument that should duck 100 % to that channel (`bassNFxChannel`, `bassNFxAmount` = 1, so none of it stays dry). The channel is ducked when the source plays.
  - Retune (kick `kickTune`, instrument `bassNTune`/`bassNOctave`), or lower/raise levels.

### Recipes (the exact steps)

**Duck instrument 2 under instrument 1** (so they stop colliding, a pump between two instruments):
1. `set_effect` channel `FX1` (any free channel), slot 1, type `Sidechain`, knobs `{"SOURCE":"Instr 1","THRESHOLD":-24,"DEPTH":0.8,"ATTACK":3,"RELEASE":200}`. The channel is ducked whenever the source plays; THRESHOLD is where ducking starts and 12 dB above it ducks fully.
2. `set_parameters` `{"bass2FxChannel":1,"bass2FxAmount":1}`: instrument 2 goes 100 % through FX1 (`bassNFxChannel` 1 = FX1; amount below 1 leaves a dry part that is not ducked).
3. `analyse_mix` again to check that the collision is gone. Undo with `undo`, or set the slot back to `Off` and `bass2FxChannel` to 0.
The source can also be the kick (`"SOURCE":"Kick"`): an effect channel ducked by the kick, as an alternative to the DUCK knobs in the SIDECHAIN tab (which already duck the instruments directly under the kick).

**The kick is covered by an instrument** (`analyse_mix` category `masking`): first check the instrument's own duck (`bassNDuck`, or the instrument's DUCK in the SIDECHAIN tab; the report says how many dB it is ducked at the kick). Raise it, or shorten the sidechain release. If it still covers the kick, cut the instrument where the kick lives with its EQ (`bassNEq2F`/`bassNEq2G`/`bassNEq2Q`, a bell at the kick's tail frequency, -3 to -6 dB) or lower its `bassNLevel`.

**Two instruments collide** (category `collision`): give them different registers (`bassNOctave`), retune if the report says they are about a semitone apart (`bassNTune`), high-pass the higher one (`bassNEqHp` 100-200 Hz) so only one owns the low end, or duck one under the other (recipe above).

**Rumble under 30 Hz**: `bassNEqHp` (or `masterEqHp`) 30-40 Hz.

**Kick tail too low/high**: `kickTune` (semitones) until `analyse_mix` reports a tail around 40-55 Hz; the tail also follows the key note.

Always verify with `analyse_mix` after a fix, and tell the user what you changed and why. Do not fix `info` findings unless asked.
